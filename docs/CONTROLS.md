# Negative controls and diagnostics (`KAROO_*_FX`, `KAROO_*_DIAG`)

Every env-var mode that makes a replacement's effect observable. The *principles* for
designing one live in CLAUDE.md ("Verify visually, not just in logs"); this is the
catalogue. Add a row when you add a mode. Plan documents (GAMETICK_PLAN.md,
RENDER_PLAN.md, PARTICLE_PLAN.md) hold the full story behind each result.

| Mode | Proves |
|---|---|
| `KAROO_PARTICLE_FX=antigrav` | gravity integration (particles rise) |
| `KAROO_PARTICLE_FX=burst` | emission (x3 initial velocity) |
| `KAROO_PARTICLE_FX=tint` / `spin` | render fill / XFace tick |
| `KAROO_FAKTMESH_FX=half` | mesh draw |
| `KAROO_TEXTURE_FX=solid` | SceneTexture loaders (fills every texture magenta) |
| `KAROO_TEXTURE_FX=bpp16` | SceneTexture format choice — *logs* the chosen format; **not visible on screen**, see RENDER_PLAN.md |
| `KAROO_SCORE_FX=tint\|nodraw` | the end-of-game overlay quads (`scoreoverlay.cpp`) — reach the high-score page with `KAROO_MENU_NODE=3` |
| `KAROO_BRIDGE_FX=tint\|nodraw\|backward` | the scrolling conveyor/bridge quads (`bridgesurf.cpp`); `backward` reverses the scroll — a direction change |
| `KAROO_BRIDGE_DIAG=1` | logs each distinct bridge `(conveyor, axis, dir, n)` variant once with its `v` coordinates — how to tell "that orientation is not drawn here" from "that orientation is mismapped" |
| `KAROO_D3DDEV_FX=mode0\|halfvp` | `Direct3D::CreateD3DDevice` (`createdevice.cpp`); `mode0` forces mode index 0 so the game comes up in a different **resolution** — a measured change, not a colour |
| `KAROO_D3D_FX=wire\|tint\|light\|nodraw` | COM proxy layer; `nodraw` returns D3D_OK from all six `DrawPrimitive*` without forwarding — a speed switch, not a visual one (see `replaytest.py --fast`) |
| `KAROO_SIM_FX=blindfoe` | the foe pathfinder's walkability test (`foepath.cpp`) — every cell reports impassable, so foes stop chasing; **7 of 12 recordings can see it** |
| `KAROO_SIM_FX=keyclash` | the pathfinder's node-key helper (`foepath.cpp`); collapses each map row to one key — a pure function whose control must break **injectivity**, since perturbing the value proves nothing |
| `KAROO_SIM_FX=popsecond` | the pathfinder's open-list pop (`foepath.cpp`); expands the second-best node instead of the best — proves the f-ordering is load-bearing |
| `KAROO_SIM_FX=nosort` | the pathfinder's f-ordered insert (`foepath.cpp`); pushes at the front so the open list goes LIFO — the write-end mirror of `popsecond` |
| `KAROO_SIM_FX=nolookup` | the pathfinder's two list lookups (`foepath.cpp`); both report absent, so every neighbour allocates a fresh node instead of rewiring |
| `KAROO_SIM_FX=nocostfix` | the pathfinder's cost cascade (`foepath.cpp`) — skips re-propagation entirely.  **Does not fail the suite**: that subsystem is exercised but unobservable, see GAMETICK_PLAN.md |
| `KAROO_SIM_FX=chaseback` | the foe chase step (`foe.cpp`) — reverses the delta-to-facing table so foes step **away** from the player along the path just found; **9 of 12 recordings fail** |
| `KAROO_SIM_FX=freestep\|revexpand\|fwdsearch\|shortsearch\|truedist` | the rest of the foe pathfinder (`foepath.cpp`); `fwdsearch` swaps the search's endpoints and fails 8 of 12 recordings — the proof that the search runs **backward**, from player to foe |
| `KAROO_FOEPATH_DIAG=1` | counts the pathfinder's re-open machinery — cascades, re-parents, worklist pushes/pops and deepest drain, logged at 1/10/100/1000/10000 cascades.  How to tell "dead code" from "live but unobserved" |
| `KAROO_SIM_FX=nopickup` | the player tick's standing-on-tile gate (`player.cpp`); no tile is ever consumed, so no gems, no items, no timed effects — **11 of 12 recordings fail**, the strongest control in the sim work.  `bridge01` is blind to it: it collects nothing |
| `KAROO_SIM_FX=deckaxis` | the bridge tick's travel axis (`bridgeobject.cpp`; was `hazardaxis`, from when the bridge was misread as a sliding hazard); flips 1<->2 at the single point the axis is read, so motion, guard and tile stamp all move together and the spike slides perpendicular — a **direction** change.  **1 of 12 recordings fails** (`bridge01`) — and that is the MAXIMUM, not weak coverage: `KAROO_DECK_DIAG=1` shows only two recordings tick a hazard at all and only `bridge01` ever arms one |
| `KAROO_DECK_DIAG=1` | logs the bridge tick's (`bridgeobject.cpp`) first tick, first extend stamp and first retract unstamp, plus a tick count every 5000 — how to tell "no hazards in this recording" from "hazards that never arm" |
| `KAROO_SIM_FX=liftflip` | the vertical lift's departure direction latch (`liftobject.cpp`); inverted at the one point it is consumed, so a platform parked at the bottom tries to FALL and one at the top tries to RISE — the whole cycle inverts.  **3 of 12 recordings fail** (`sandra02`, `thrower02`, `thrower02_fly`); `KAROO_LIFT_DIAG=1` shows 6 tick a lift at all |
| `KAROO_LIFT_DIAG=1` | logs the vertical lift's first tick, first completed rise, first completed fall and first depart, plus a tick count every 5000 — the sweep that showed 6 of 12 recordings move a lift and 5 exercise all three states |
| `KAROO_SIM_FX=blockstay` | the slide's vacated-tile release (`slideobject.cpp`; named when the slide was misread as a pushable block); the slide advances but never clears the tile behind it, so it leaves a trail of solid cells instead of sliding through — a change to what the world is made of, not merely where the slide is.  **1 of 12 recordings fails** (`thrower02`); `KAROO_BLOCK_DIAG=1` shows 5 tick a block and all 5 exercise every path |
| `KAROO_BLOCK_DIAG=1` | logs the slide's first tick, first vacate, first completed advance, first completed retreat and first depart, plus a tick count every 5000 — the sweep that showed all four paths are exercised by 5 of 12 |
| `KAROO_SIM_FX=nocontact` | the foe step's contact latch and hit flag (`foe.cpp`); a foe can stand on the player without ever registering a touch.  **1 of 12 recordings fails** (`thrower02`) — and that is the CEILING: `KAROO_FOESTEP_DIAG=1` shows `thrower02` is the only recording in which any foe ever makes contact |
| `KAROO_SIM_FX=foeunfreeze` | the foe step's freeze gate (`foe.cpp`); frozen foes keep chasing.  **Does not fail the suite** — yet the diag proves the gate fires in at least four recordings, so this is live-but-unobserved code, the same category as `nocostfix`.  See GAMETICK_PLAN.md |
| `KAROO_FOESTEP_DIAG=1` | logs the foe step's first tick, contact, tile consume, chase direction, turn-table entry, return-to-post and frozen foe — the sweep that found three of its paths are reached by no recording at all |
| `KAROO_SIM_FX=keepid` | the despawn pair's ID free-list compaction (`objectremove.cpp`, shared by `foe.cpp`'s remove and `bomb.cpp`'s); the removed ID is never lifted out, so the list keeps a stale entry and every later tick addresses the WRONG object — **5 of 16 recordings pass**.  It was silently dead from ff4531b to the Band 6 fix (the tail never called its `fx_init()`) — COHESION_PLAN.md, Band 6 |
| `KAROO_REMOVE_DIAG=1` | logs the first foe removal (`foe.cpp`), bomb removal (`bomb.cpp`), sound release, virtual destructor call and compaction shift, plus a count every 500 |
| `KAROO_SIM_FX=spawnswap` | the spawn pair's tile coordinates (`foe.cpp` for foes, `bomb.cpp` for bombs); u and v exchanged at the single point they are read, so all six coordinate stores, the three floats, the home target and the tile stamp move together — a coherent **position** change.  **5 of 14 recordings pass**.  Note `levelreport.py` is BLIND to it: it builds every object but does not observe coordinates |
| `KAROO_SPAWN_DIAG=1` | logs the first foe spawn, bomb spawn, high type, kind-2 and kind-3 foe and sound acquisition, plus a count every 500.  Under `levelreport.py` it also censuses the whole foe-type alphabet across all 80 levels and names every level carrying a type above 0x64 — that census is how `freeze03` and `enemyfactory` were chosen |
| `KAROO_SIM_FX=blockinvert` | the listed-tile blocking pass (`tilequery.cpp`); inverts the blocked flag, so the tiles an object blocks become exactly the tiles it does not — a change to what the world is made of, not to where anything is |
| `KAROO_SIM_FX=listfar\|radiusfar\|farnear` | the three tile *searches* (`tilequery.cpp`); each reverses which member of the candidate set wins — the two nearest-searches pick the farthest, and the farthest-search picks the nearest.  Deliberately does NOT flip the accept or success test: that would empty the candidate set and degrade the control into "always fail", the same reasoning that made `keyclash` break injectivity rather than perturb a value |
| `KAROO_TILEQ_DIAG=1` | logs the first call to each of the four tile queries and the first successful RESULT from each, plus a call count every 5000 — how to tell "this recording never calls the query" from "it calls it and never gets a hit" |
| `KAROO_SIM_FX=placeaxis` | the lift and breakable spawns (`liftobject.cpp`, `breakabletile.cpp`); exchanges u and v at the single point each reads them, so object fields, float mirrors and tile record move together.  **9/16 recordings pass** — and unlike `spawnswap`, `levelreport.py` is NOT blind to it (~20 levels diff), because these spawns stamp a tile marker that `SetupLevelObjects` reads back when placing further objects |
| `KAROO_SIM_FX=slideaxis` | the slide spawn's two track kinds (`slideobject.cpp`); exchanges them, so a track meant to run along U is scanned along V — scan, stamping and recorded span move together.  **15/16**, and `levelreport.py` PASSES.  That 1 failure is **NOT a ceiling**: `KAROO_PLACE_DIAG=1` shows `water01` builds 13 slides across both branches and still passes, because a track's axis only reaches an asserted field if the player RIDES it |
| `KAROO_SIM_FX=bridgespan` | the bridge spawn's far-end computation (`bridgeobject.cpp`); exchanges the forward/backward arms that set `+0x38`, so a bridge records the wrong extent while its SCAN is untouched and stays in bounds.  **15/16** (`bridge01` — the player falls: `lives` 3→2, `vitality` 87→0), `levelreport.py` PASS.  Replaces `bridgeaxis`, which was REJECTED for CRASHING rather than relaying — see GAMETICK_PLAN.md, and note a crash reports as a FAIL, so the pass column alone could not tell them apart |
| `KAROO_PLACE_DIAG=1` | logs the first lift spawn, the first failed allocation, a spawn count every 500, and **every slide and bridge spawn with its kind/axis** (`SCAN-U` / `SCAN-V` / `no-scan`) — the census that showed `slideaxis`'s single failure is weak coverage rather than the maximum available |
| `KAROO_SIM_FX=keepobjects` | the level teardown's four purges (`gamereset.cpp`); all four return immediately, so objects AND their counts survive and the next level would tick the previous level's.  **Does not fail the suite** — and `KAROO_RESET_DIAG=1` shows this is structural, not weak coverage: the only purges that destroy anything run at the FINAL teardown, after every asserted field is captured.  See GAMETICK_PLAN.md |
| `KAROO_RESET_DIAG=1` | logs the first call to `ClearGameState` and each of the four purges, the first sound release, virtual destructor, foe drain and enemy drain, plus every **LIVE** purge — one entered with a nonzero count, the only kind that destroys anything.  That last counter is what distinguishes "the suite never tears down a populated level" from "it does, and the control still cannot see it" |
| `KAROO_SIM_FX=stacktop` | the menu node stack's pop (`menutree.cpp`); reads one entry PAST the top — the only single-sided edit that changes anything, since the function's off-by-one base and off-by-one index cancel.  **Does not fail the suite**: `KAROO_MENUSTACK_DIAG=1` shows a recording pops twice and both pops are instantly overwritten.  Live-but-unobserved, like `nocostfix` |
| `KAROO_SIM_FX=menuroot` | **REJECTED, kept as a cautionary control** — the menu rewind seeds the cursor at 1 (`menutree.cpp`).  Fails **all 16** recordings and means nothing: every asserted field still matches and only `frames_run` moves by +1, because `menu.cpp`'s driver re-routes around the moved cursor.  Same signature as a music-on config.  The `bridgeaxis` lesson inverted — read the failing FIELDS, never the pass column |
| `KAROO_MENUSTACK_DIAG=1` | logs the first menu-stack push, pop and rewind and then EVERY call with running counts and max depth — a census, not a sample, because the whole family is called under a dozen times per recording |
| `KAROO_SIM_FX=levelshift` | the level-name table lookup (`levelparse.cpp`); reads entry N+1, so every load opens the NEXT level.  **0/16**, with real field diffs and no crash — the acceptance evidence that the replacement loaders are the live, correctly-indexed path.  Near-tautological as a control (a replay replays keypresses), so it does not isolate anything *inside* the loaders |
| `KAROO_SIM_FX=samelevel` | both level loaders' map-name copy (`levelparse.cpp`); moves it AFTER the read so the `+0x10` "map changed" flag is stuck at 0.  **Does not fail the suite** even though the diag proves it flips the flag — live-but-unobserved, like `nocostfix` |
| `KAROO_LEVELPARSE_DIAG=1` | logs every call to EITHER level loader with the level name/number, map result, `+0x10` flag and script counter, plus the bonus peek and the first extra-object sound release — the diag that revealed `ParseLevelFiles` and `OpenLevelFile` are duplicates and that recordings only execute the latter |
| `KAROO_SIM_FX=noshadow` | the level builder's type-0x17 item→shadow move (`levelsetup.cpp`); items stay in the other pair of census counters.  Fails **both** gates — `levelreport.py` diff and replay **15/16** — and touches counting only, never geometry, so it cannot reach an unbounded spawn scan |
| `KAROO_SIM_FX=setupflip` | the level builder's tilemap walk (`levelsetup.cpp`); transposes u and v at the one point the index is formed.  **1/16** on the replay suite (verified real: full-length runs, no AV, real fields) but it **CRASHES `levelreport.py`** — moving geometry re-triggers the bridge/slide spawns' unbounded scans.  Valid on one gate only; never cite the level-report failure |
| `KAROO_SETUP_DIAG=1` | logs each `SetupLevelObjects` call with the map extents and the full per-kind census — crystals, total, bridges, teleports, lifts, slides, breakables, foes, free bombs, timed items, switch max |
| `KAROO_GAMELOG_FX=mark\|off` | the game's own logger (`gamelog.cpp`); `mark` prefixes every line it writes with `KHOOK `, `off` suppresses the message writes but keeps the banner |
